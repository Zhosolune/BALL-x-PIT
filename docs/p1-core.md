# P1：离线决策核心交付

日期：2026-10-09。状态：已完成离线核心与场景检查，没有接入游戏、加载器或 UI。

## 运行

在项目根目录执行：

```powershell
./scripts/run-p1.ps1
./scripts/run-p1.ps1 -Demo
```

第一条构建并执行所有场景，失败时以异常和非零退出码报告。第二条展示人工数值推荐；保存的演示见 [p1-demo.json](p1-demo.json)，其中 purpose 明确说明不是真实游戏推荐。

核心使用 C# / net8.0，无 Unity、BepInEx 或第三方 NuGet 依赖。测试为可执行的轻量场景检查程序，不是需要额外测试适配器的 dotnet test 项目。离线计算使用的目标框架不代表未来插件的运行时已经确定；P2 需按实际加载器验证或调整目标框架。

## SDK 与构建环境

已安装 Microsoft 官方 .NET SDK **8.0.425**，路径为 `.tools/dotnet`。通过官方发布元数据 `https://dotnetcli.blob.core.windows.net/dotnet/release-metadata/8.0/releases.json` 获取版本，使用 `https://dot.net/v1/dotnet-install.ps1` 下载 Windows x64 SDK。安装没有修改系统 PATH；global.json 锁定实际版本。

SDK 和构建缓存不纳入版本控制。其他开发者需要在项目内准备同版本 SDK；可执行以下命令：

```powershell
New-Item -ItemType Directory -Force .tools | Out-Null
Invoke-WebRequest https://dot.net/v1/dotnet-install.ps1 -OutFile .tools/dotnet-install.ps1
& ./.tools/dotnet-install.ps1 -Version 8.0.425 -InstallDir "$PWD/.tools/dotnet" -NoPath
```

`run-p1.ps1` 临时将 CLI 配置和缓存指向工作区，关闭遥测、后续开发证书自动生成及全局工具 PATH 修改；退出时恢复进程环境和目录。NuGet.Config 暂时清空包源，因为 P1 没有包依赖；P2 引入加载器时需显式配置来源及版本。

## 已实现的行为

- 新物品获取、已有物品升级、已知进化条件的操作模拟；原始快照和集合保持不变。
- 独立弹珠/被动槽位、重复输入拒绝、材料数量与等级检查、消耗和结果等级处理。
- 融合与未知物品保持 Unassessed；未知等级、槽位、消耗或收益不补默认值。
- 三步有界规划，默认每层二十个状态、最多一千次已知规则展开。条件结构另有一千次预算，两类预算独立。
- 按装备内容检查路径循环，同一配方可为不同实例合法重复制作；消费后的材料不会继续被视为拥有。
- 多材料和替代方案分别保留；缺失物品、升级需求及每一步材料完整记录。
- 角色直伤限制和范围系数只作用于对应人工收益通道；条件协同要求同时存在来源与目标效果。
- 候选基于选择后的状态增量，路线基于最终状态与起点的增量，数值完整时给出分项、分数和理由。
- 原始效用排名，画面顺序/候选 ID 稳定处理并列；存在未评估项时仅推荐已评估项。
- 结果附本局、状态、界面和规则版本，任一不匹配都不能用于当前 UI。

## 评分与路线细节

人工校准参数版本为 synthetic-calibration-0.1，与 P0 真实物品分离。默认材料获取成本 8、升级成本 2、步骤成本 1、发展潜力权重 0.5、接近阈值 1；这些只用于离线算法验证，不是已校准的游戏策略。

状态效用拆为基础、角色修正和组合协同。候选效用为操作前后这三项的差，加上最佳正路线收益变化乘发展潜力权重。这样不会只因路线多而高分，也会扣除放弃原有发展方向的影响。

路线效用 = 最终状态效用 − 路线起点效用 − 缺失材料成本 − 升级成本 − 步骤成本。进化时失去的装备已经体现在状态差中，不能再重复扣除。ScoreParts 的直接获取/机会成本目前为零，因为候选免费选择的消耗已包含在状态差和前瞻差；未来真实操作具有额外成本时才增加对应规则。

显示映射为 `round(50 + 50 × tanh(原始效用 / DisplayScale))`，默认 DisplayScale=5。这个固定映射用于演示，排名始终依据未取整的原始效用，即使显示分数相同也不误判真实并列。0–100 分不是胜率。

原样加载社区数据时，角色与等级收益未校准，所有真实候选保留 Partial/Unassessed，不产生确定首选。模拟人工进化成功只证明状态转换实现正确，不会将其变为真实游戏规则。

未知条件的社区配方只生成结构路线：路线状态为 UnknownRequirements、总分/升级需求/最终状态为空。MissingMaterials 是当前快照与路径结构给出的缺失下界；因真实消耗未核验，不能用该列表宣布可执行或精确总材料成本。

## 当前限制与下一步

- 当前测试使用人工收益；真实逐级数值、协同权重、进度压力和正式分数校准留待 P2/P5。
- 融合只返回待评估，不模拟未核实的融合机制。
- 有界搜索按已知配方扩展，不模拟未知随机掉落、不枚举任意物品丢弃、不证明全局最优。
- 同种材料优先选择高等级实例减少升级需求；尚未枚举所有实例组合的机会成本。
- 未知条件路线只做结构分析；已知规则和未知规则之间不伪造混合执行链。
- 宿主线程或取消任务尚未接入；本阶段通过不可变数据和版本检查为其准备边界。

下一步 P2 需要目标游戏版本的 interop 类型和实际测试环境：读取角色、全部候选、装备等级、融合组成和界面事件，核对配方条件，锁定加载器与运行时。该环境可以在用户电脑或其他测试者电脑，当前工作区未安装游戏。
